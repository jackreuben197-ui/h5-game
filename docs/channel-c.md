# 渠道 C 产品说明

本文维护渠道 C 的页面、交互和业务规则，供产品、设计、运营及验收使用。开发环境、接口维护和跨端实现见 [开发说明](../README.md)。

## 1. 适用范围与导航

渠道 C 面向当前渠道俱乐部，使用其真实可见的牌桌、比赛、活动和品牌配置。版本由后台配置决定；C 对应 `h5_menu=3`，A/B 保留各自入口和行为。

| 入口 | 页面 | 主要内容 |
| --- | --- | --- |
| 主页 | `/home` | 品牌区、搜索、账号入口、五个活动入口、主题开关、Banner、热门推荐 |
| 牌桌 | `/channel/tables` | 玩法 / 盲注筛选与牌桌列表 |
| 比赛 | `/channel/matches` | 比赛类型 / 分类筛选与赛事列表 |
| 充值 | `/wallet` | 复用现有钱包及充值流程 |
| 我的 | `/mine` | 复用现有个人中心 |
| 搜索 | `/channel/search` | 全屏名称 / ID 搜索，不显示底部菜单 |

底部菜单固定为“主页、牌桌、比赛、充值、我的”。旧牌桌 / 比赛入口会按当前菜单版本进入对应页面。

消息页隐藏底部菜单，左上角提供返回按钮；点击返回上一页，没有站内历史记录时返回主页。

## 2. 身份与主页入口

| 状态 | 顶部右侧 | 俱乐部管理 |
| --- | --- | --- |
| 未登录或体验账号 | 搜索左侧显示注册、登录按钮；隐藏消息与头像 | 隐藏 |
| 真实账号，未加入当前俱乐部 | 搜索、消息、头像 | 隐藏 |
| 真实账号，已加入当前俱乐部 | 搜索、消息、头像 | 主页右下角显示管理入口 |

注册、登录与 A/B 共用按钮样式和登录弹窗模式，文字水平、垂直居中。登录成功后自动恢复消息和头像入口。消息进入消息页，头像进入资料编辑；管理入口进入当前俱乐部详情。

游客可以浏览列表和比赛详情、进入普通牌桌观战；入座、报名、充值提交及奖励查询等真实身份操作沿用登录校验。取消登录时保留预览，普通大厅操作登录成功后可继续原动作；牌桌内入座使用专门的身份切换和重新进桌流程。

## 3. 主页内容

顶部依次展示品牌标识、搜索 / 账号入口、活动入口、主题开关和 Banner。

五个活动入口为：对局奖励、活动公告、充值有礼、邀请有礼、在线客服。公告与客服复用现有功能；公告可展示俱乐部公开内容。从活动公告主动打开时不显示“今日不再提示”，自动弹出的公告保留原有规则。

主页只展示后台标记为热门、且当前用户可见的牌桌和比赛；没有推荐内容时显示空状态。牌桌和比赛分别排序后，以“3 张牌桌 + 1 张比赛”顺序混排，一类不足时保留另一类的剩余内容。

推荐、牌桌、比赛和搜索结果使用相同的卡片样式与两列瀑布流：首排顶端对齐，后续卡片进入较短列，列内保留排序。返回列表时恢复对应页面的滚动位置。

Banner 优先使用俱乐部 C 版配置，没有时使用平台 C 版配置；均无可用图片或加载失败时使用本地默认 Banner。C 图参考尺寸为 `372 × 69`，不混用 A/B 服务端图片。

## 4. 牌桌列表与筛选

玩法下拉框包含“全部牌桌、德州、奥马哈、短牌”。具体玩法可多选，“全部”清空玩法限制。

盲注从当前俱乐部完整可见牌桌动态生成，去重并升序排列；不固定级别数量，超出一行可横向滚动，玩法下拉框保持可见。玩法和盲注分别支持多选：同组取并集、不同组取交集。切换玩法不清除盲注，后台移除某盲注时仅清理对应失效选项。

选中的下拉框、盲注和分类按钮显示蓝底白字，深浅主题均保持清晰。筛选无结果时可重置。

牌桌顺序依次考虑“已参与且未满、新桌且未满、已参与且满、其他”，同级使用创建时间倒序。

### 牌桌卡片

| 区域 | 展示规则 |
| --- | --- |
| 牌桌背景 | 根据德州、奥马哈、短牌展示对应桌面 |
| 人数与座位 | 展示真实人数及玩家头像，空座不补假头像；座位布局按桌位上限保持稳定 |
| 中央第一行 | 有特殊玩法时先展示文案、再展示放大的图标，文案为“鱿鱼桌”“暴击桌”“蘑菇桌”等；无特殊玩法时展示基础牌桌类型，两者择一 |
| 中央第二行 | 剩余 / 总时长，未开局显示完整时长，到期显示 0 |
| 简介与特色 | 有内容才显示，缺失时不占空行 |
| 底部信息 | 桌面图标、牌桌名、大小盲、最低买入、加入按钮 |

底部头像与保存到手机桌面的应用图标共用解析逻辑，使用 `safari_icon_url`。配置优先级为俱乐部应用配置 ＞ 联盟应用配置 ＞ 平台默认配置；服务端按俱乐部、联盟优先级返回最终字段，空值或无效地址回退平台默认桌面图标，图片加载失败也回退平台图标。首页、牌桌页及搜索结果保持一致，不使用牌桌内图标 `room_logo`。

8 人桌的最后一位居中；9 人桌的最后两位分居底部两侧，不随临时人数变化而跳位。3、4、5 号位头像略向上调整，保持桌面中央信息清晰。

最低买入沿用现有牌桌规则：大盲金额 × 最低买入 BB 倍率。点击卡片任意位置（含加入按钮）沿用真实进桌流程，进入中避免重复触发。

## 5. 比赛列表与卡片

赛事类型下拉框使用后台配置的全部有效类型，不因当前没有比赛而隐藏某类型。具体类型可多选，“全部比赛”清空类型限制。

免费赛、收费赛、猎人赛、滚雪球赛四个分类可多选；同组取并集，与赛事类型取交集。免费 / 收费以报名费判断，特殊分类沿用服务端赛事配置。

排序优先级为已报名、报名中、等待报名、进行中、已结束；同级按开始时间升序。

卡片展示封面、赛事状态、可选赛事标签、多语言名称、奖池、开始时间、报名人数和报名按钮。未报名显示“报名”，已报名显示“已报名”。名称支持服务端多语言模板及编号后缀，切换语言或模板加载完成后自动更新；没有名称时用赛事 ID 兜底。点击卡片任意位置（含按钮）进入比赛详情，报名和入场沿用原流程。报名人数使用 HTTP / WebSocket 的 `participants`，详情刷新后同步列表人数。

| 规格 | 封面比例 | 尺寸规则 |
| --- | --- | --- |
| 大卡 | `180:225` | `series_id` 对应系列配置 `type=1` |
| 中卡 | `180:152` | `type=2`；无系列、找不到系列或类型无效时默认中卡 |
| 小卡 | `180:89` | `series_id` 对应系列配置 `type=3` |

尺寸直接按系列配置确定，不因系列场次数、推荐、筛选或搜索结果数量变化。C 封面缺失或加载失败时使用对应规格的本地占位图。

## 6. 搜索

搜索覆盖完整可见牌桌和比赛，不受热门标记限制，支持名称与 ID 的部分匹配、忽略大小写、首尾空白及全角字符归一化。

MTT 名称按当前语言解析服务端多语言模板后匹配，保留编号后缀，与卡片展示名称一致；切换语言或模板加载完成后自动重新匹配。

| 状态 | 展示 |
| --- | --- |
| 关键词为空 | 仅显示搜索框与取消按钮 |
| 有关键词，数据未就绪 | 显示加载状态 |
| 有结果 | 使用共用卡片与瀑布流，保留各自排序并按 3 桌 + 1 比赛混排 |
| 无结果 | 显示“暂未找到相关游戏”与部分名称搜索提示 |

搜索页不显示底部菜单；取消返回主页。进入详情后返回可恢复关键词，输入过程不为每次修改增加历史记录。

## 7. 活动奖励

三个奖励弹窗均读取服务端实际配置与当前玩家数据。游客点击先登录；加载中、无配置、失败重试分别展示对应状态。切换俱乐部或账号时不能混入上一位玩家的进度。

| 活动 | 展示与操作 |
| --- | --- |
| 对局奖励 | 按后台小盲和手数条件展示档位、当前手数、UC / 门票奖励与发放状态；保留零币、空门票的条件档位 |
| 邀请有礼 | 展示有效邀请人数、全部阶梯条件、各档进度与到账状态 |
| 充值有礼 | 分首充 / 日常两种配置，展示充值区间与奖励；跳转现有钱包，不将配置区间当作玩家累计充值进度 |

奖励状态以服务端结果为准：未达标显示进度；达标或已建单但尚未发放显示待发奖；明确发放成功才显示已到账。通知已经发送不等于奖励已经到账。

UC 奖励和充值区间直接按 UC 展示；盲注和门票面值从服务端分单位换算，避免重复缩小 100 倍。门票名称使用服务端多语言名称。

有效手数、邀请有效性、俱乐部绑定、统计和发奖由服务端负责，前端展示和刷新数据，不自行累加进度或钱包余额。

### 到账通知

到账可包含 UC、门票或两者，并区分对局、邀新和充值来源。同一订单只展示一次；旧通知先到时，完整活动通知可补全该订单的奖励内容。

活动奖励在 H5 可见时展示，牌局中收到则回到大厅后展示；登出或切换账号清理待展示队列。收到相关通知后刷新同俱乐部或同联盟中已打开的奖励弹窗。

## 8. 邀请分享与注册归因

邀请页面生成的分享链接、预览二维码和保存图片中的二维码使用同一份完整链接。

普通邀请：

```text
https://{分享域名}/#/?invite_code={俱乐部邀请码}&mode=register&random_id={邀请人玩家ID}
```

代理邀请：

```text
https://{分享域名}/#/?mode=register&i={代理邀请码}&random_id={邀请人玩家ID}
```

分享域名依次取俱乐部独立域名、`俱乐部邀请码.平台二维码域名`、当前域名。管理员、代理和普通玩家分享都携带邀请人的玩家随机 ID，不使用内部用户主键或俱乐部 ID 冒充邀请人。管理员和普通玩家入口读 `user/info.user.un_id`；代理可使用俱乐部用户详情返回的 `user_info.random_id`，缺失时回退到当前玩家 `un_id`。

打开邀请链接后保留本次邀请码和邀请人信息，跨页面后注册将链接中的 `random_id` 映射为两个注册接口的数字字段 `inviter_random_id`，兼容历史同名链接字段。`invite_code` 沿用既有规则：代理邀请使用 `i` 中的代理码，其他邀请使用俱乐部码；`inviter_random_id` 对所有邀请角色均提交。代理绑定与邀新归因同时保留，不能因为 URL 带 `i` 而丢弃邀请人 ID。成功登录 / 注册后清除邀请缓存；新邀请不能沿用另一邀请码对应的邀请人。

## 9. 主题、布局与内容边界

支持简中、繁中、英文、葡语及深色、浅色、跟随系统主题。长名称、省略、筛选选中态和按钮在不同语言与主题下保持可辨认、可操作。

主页、牌桌页、比赛页使用共用滚动容器，并为底部菜单和系统安全区预留空间；滚到底后，最后一张卡片及其按钮必须完整可见。主页出现俱乐部管理悬浮入口时额外留白，避免入口挡住末张卡片。手机、Pad、桌面均遵循这一要求。

牌桌页和比赛页的顶部筛选栏随列表滚动保持吸附在可用区域顶部，避开系统安全区；筛选栏使用当前主题的实色背景并覆盖下方卡片，滚动后仍可操作下拉框、横向选项及多选筛选。

后台取消热门、清空简介 / 特色、移除活动配置或清空 C 图后，页面应同步更新，不用旧缓存恢复已清空内容。列表、报名状态和活动进度均以真实服务端数据为准。

## 10. 验收场景

- 用游客、已登录未入会、已登录已入会三种身份检查入口显示和登录续接。
- 检查首页推荐、组合多选、无结果重置、搜索返回恢复，以及牌桌 / 比赛真实跳转。
- 用 8 / 9 人桌、特殊玩法、缺省文案、失效封面、不同赛事系列数量检查卡片。
- 用长列表、多语言、深浅主题和底部安全区检查末项与操作按钮，管理入口不遮挡内容。
- 使用测试账号检查邀请二维码到注册的归因，以及奖励加载、待发奖、到账、同单去重、牌局中排队和账号切换。

本文是产品规则与验收依据；开发测试结果以实际执行记录为准，不把某次本地测试项数或构建版本作为长期产品规则。
